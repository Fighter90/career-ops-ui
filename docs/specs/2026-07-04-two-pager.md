# Spec — The Two-Pager: candidate market fit (v1.89.0, roadmap Epic 14)

**Status:** in progress · **Date:** 2026-07-04 · **Release:** v1.89.0
**Goal:** Match the candidate against what they *actually want*, not just what their CV says — a guided two-pager (Mnookin "Never Search Alone" format), an AI draft assistant, a **fit-to-what-you-want** sub-score on vacancy cards, and the two-pager fed into every evaluation.

## Data model & storage (parent boundary)

The two-pager is user career-framing content → lives in the **user layer** as a new web-ui-owned file **`config/two-pager.yml`** (never overwritten by parent updates; consistent with `config/profile.yml`). Structured blocks:

```yaml
who_i_am: ""            # short first-person "Who I am" narrative
loves: []               # what energizes them (positive signals)
must_haves: []          # non-negotiable requirements (positive, hard)
hates: []               # what drains them (negative signals)
deal_breakers: []       # hard nos (negative, hard)
target_environment: ""  # company size/stage/culture they want
non_negotiables: []     # boundaries (comp floor, location, remote, …)
```

`PATHS.twoPager = config/two-pager.yml`. Writes only on an explicit **Save** (PUT) — same write-through contract as `PUT /api/cv`.

## Architecture

- **`server/lib/routes/two-pager.mjs`** — `registerTwoPagerRoutes(app)`:
  - `GET /api/two-pager` → parsed YAML (empty-safe default structure).
  - `PUT /api/two-pager` → validate shape (arrays/strings, size caps), write via `withFileLock`. Rate-limited/loopback-safe like other writes.
  - `POST /api/two-pager/draft` (LLM, `llmRateLimit`) → generate a Mnookin-format two-pager draft from `cv.md` + `config/profile.yml` (+ any partial blocks the user already filled), for the "AI fill assistant". Reuses the existing provider/prompt plumbing; one-shot draft the user then edits (a full conversational interview is a later enhancement, shared with E2 mock-interview).
- **`bundleProjectContext`** (`prompts.mjs`) — add `{ label: 'config/two-pager.yml', path: PATHS.twoPager }` to the inlined file list so **every** evaluation/deep/mode prompt sees it. A short directive frames loves/must-haves as positive signals and hates/deal-breakers as negative, blended with the CV-vs-job match.
- **`public/js/lib/fit-score.js`** — pure `window.FitScore`: score a scan job row (`{title, company, location, workplaceType, isRemote, salary, relocates}`) against the two-pager's **structured, matchable** prefs (work-type loves/hates, country must-haves/deal-breakers via `window.Countries`, salary floor from `non_negotiables`) → `{ score: 0–100, matched: [...], violated: [...] }`. Free-text semantic prefs that can't be matched to a row are **not** guessed here (they influence the full LLM eval instead) — honest, no fabrication.
- **`public/js/views/two-pager.js`** (`#/two-pager`) — guided builder: an editable card per block (list editors for the arrays, textareas for narratives), an **✨ AI draft** button (calls `/api/two-pager/draft`, previews before overwriting, never clobbers manual edits silently), **Save**. Nav item under Setup.
- **`public/js/views/scan.js`** — when a two-pager exists, render a **fit** badge per row from `FitScore` (colour by score band) with a tooltip listing matched/violated criteria, next to the existing work-type badge.

## Security / boundaries
- Only write is `config/two-pager.yml` (user layer) on explicit Save. No CV/profile mutation. `POST /draft` sends CV+profile to the active LLM provider (same trust boundary as `/api/evaluate`); no new external surface. CSP-safe (SVG/`addEventListener`), no new deps (YAML via existing `js-yaml`).
