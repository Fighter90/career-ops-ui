## Executive summary

The release is a patch by size but a hardening wave by content: every mutating relay
CodeQL flagged now sits behind a canonical, analyser-recognised limiter
(`express-rate-limit@7.5.1`), the evaluation timeout contract is one number for all
locales (killing a whole class of transient 502 · 300 s findings like the es/zh-CN ones
remote-QA caught), and the cvstart.org FAQ counts can no longer drift from the app
because they are generated from the live registry. The review's own security pass found
**no HIGH/MED issues**; three LOW observations (reverse-proxy bucket degeneration,
`validate:false`, the residual unthrottled mutating surface) and three informational
confirmations are recorded below. Post-release, `92a05fcf` fixed a real process gap the
review confirms mattered: the site-build-after-fanout grader had only ever passed via
its no-mirrors SKIP — the mirror stamp makes it exercise real logic for the first time.

## Findings (this review's own pass)

No HIGH, no MED. Three LOW observations for the next hardening wave, three
informational confirmations.

| # | Sev | Where | Finding |
|---|---|---|---|
| 1 | **LOW** | `server/lib/rate-limit.mjs:197-198` | **Bucket degeneration behind the reverse proxy.** No `trust proxy` is set anywhere (repo-wide grep), so `req.ip` is the socket address; on resumecraft.ru every remote client shares Caddy's socket address and the per-(route × IP) key degenerates to a **per-route global bucket** — one credentialed flooder can 429-lock other users of that endpoint for ≤60 s. Mitigated: basic auth in front, single-user product, 60/min is generous. The flip side is deliberate and correct: X-Forwarded-For is ignored → **no spoofing bypass** of the key. If per-client keying on prod is ever wanted, it must come with `trust proxy` + a re-derived keyGenerator (see #2) |
| 2 | **LOW** | `server/lib/rate-limit.mjs:212` | **`validate: false` disables express-rate-limit's misconfiguration checks.** Justified in-code for today's shape (loopback single-user, no trust proxy — the ER_* warnings would only add noise). But it also silences future-misconfig detection: if `trust proxy` is ever enabled without reworking `keyGenerator`, X-Forwarded-For spoofing becomes a limiter bypass and nothing will warn. Condition to remember: *enable trust proxy ⇒ re-enable validations or derive the key from a trusted, verified header* |
| 3 | **LOW** | repo-wide survey | **Residual unthrottled mutating surface.** `writeRateLimit()` covers 2 of ~19 mutating POST routes. Still unthrottled: `/api/run/{doctor,verify,normalize,dedup,merge,sync-check,reconcile}` (7 subprocess relays, three of them tracker-mutating), `/api/runners/posting-guard` (spawn), `/api/tracker/import-csv`, `/api/tracker/backfill-scores`, `/api/pipeline(+/restore)` (data writes), `/api/portals/toggle|health`, `/api/jds`, `/api/export/docx`, `/api/apply-helper`, `/api/reports`, `content.mjs:84`. CodeQL flagged only report-links/tracker-status — its heuristic, not a proof the rest is safe; the same runaway-client argument applies. Mitigations today: loopback bind + request-guard Host allowlist + basic auth on prod. Natural next-wave item: extend `writeRateLimit()` across the spawn/write relays |
| 4 | **INFO** | `server/lib/routes/llm.mjs:51-56` | 480 s ceiling now uniform — the worst-case wall clock per evaluation was already 480 s for token-dense locales since CAR-147; the change makes it the norm, not a new worst case. Token burn bounded by `evalMaxTokens` + the disconnect abort (FULL-M5); proxy timeout demonstrably ≥480 s (remote-QA ran real evaluations). No action |
| 5 | **INFO** | `public/js/lib/nav-v2.js:377-384` | `syncLabelTitles` is XSS/CSP-clean: `label.title = t(key, label.textContent)` is a DOM property assignment (no HTML parsing, no `innerHTML`), both inputs are app-owned i18n dictionary content — no user data flows in. R-07 intact |
| 6 | **INFO** | `site/scripts/sync-assets.mjs:110-114,195-199` | Mirror stamp is injection-free: `SITE_VERSION` comes from `package.json` (repo-controlled); the footer has no `](` links so `rewriteRootLinks` is a no-op on it; the `countReleases` tripwire counts `## [` headers, which the italic footer cannot fake — the read-back cross-check stays meaningful |
| 7 | **INFO** | `server/lib/rate-limit.mjs:53-62,186` | No unbounded store growth: the LLM limiter keeps `MAX_BUCKETS` eviction + sweep (store-refactored, behavior unchanged); each `writeRateLimit()` store is an express-rate-limit `MemoryStore` with an unref'd sweep interval every `windowMs` (v7.5.1 source-verified), keyed by (route path × clientKey) — bounded by distinct addresses within a 60 s window. Two production stores total. The 429 limiter counting handler-rejected 400s is intended and documented in the test header |
