# SPEC — v1.262.1: it token-dense + provider/hermes deploy modes

> Status: SHIPPED (the release spec; Verification filled with real output before the release merged).
> One patch, two halves of one incident: the `it` evaluation cut caught by the OpenRouter-era
> remote-QA, and the deploy-workflow ops tooling that made the provider triage possible (CAR-190 tail).

## Goal

The first remote-QA run on the refilled OpenRouter credits (**40928864980**) caught an `it`
evaluation running 264 s and coming back cut right before the `---SCORE_SUMMARY---` block —
`tok ~15635` at the 16 384 ceiling, Blocks A–G intact. The same shape class that earned `ta`
its ceiling in v1.261.1 (CAR-174). Give `it` the token-dense budget, and ship the
`mode=hermes` / `mode=provider` deploy ops that were used live to diagnose the credits
exhaustion and move prod to `openrouter`.

## Scope

1. **`it` → `TOKEN_DENSE_EVAL_LOCALES`** (`ta`, `hi` → `ta`, `hi`, `it`, `server/lib/routes/llm.mjs`):
   both the 32 768-token budget and the 480 s clock apply; `/api/evaluate` and auto-pipeline
   stay on the one source of truth (`evalMaxTokens`). Red-first in
   `tests/evaluate-truncation.test.mjs` — the case asserting `evalMaxTokens('it') === 16384`
   fails against the old map, `it`/`it-IT` at 32768 asserted after (#603).
2. **en blockless report = one-off generation flake, deliberately not added**: the same run
   saw a single `en` evaluation come back language-correct with **none** of the A–G blocks;
   a targeted re-run passed clean. One flake is not a volume history — recorded in
   CHANGELOG Notes, QA prompt §3 and the release review.
3. **Deploy ops (CAR-190 ops tail)**: `mode=hermes` (Hermes gateway restart + full redacted
   diagnosis: unit file with secrets stripped, listeners before/after, sudo journal, per-port
   probes incl. the claude-bridge on 8788, the app's own `HERMES_BASE_URL` view, provider-key
   inventory — names only, OpenRouter credits balance — numbers only) and `mode=provider`
   (switch `LLM_PROVIDER` with a key-presence guard — refuses when the target provider's
   `*_API_KEY` is absent — + service restart; this is how prod moved to `openrouter`).
   The deploy-only ref guard replaces the #591 required inputs, so `recon`/`verify` dispatch
   again; gate 690 fixed via env-carried inputs (#593/#594/#595/#596/#598/#599/#600/#601).

**Out of scope (deliberate non-actions)**:

- Recording the new UI-v2 demo video — CAR-141, owner-gated; the landing embeds via
  `youtube-nocookie.com` regardless (#602).
- Extending the ta reinforced-language directive to `it` — no language drift observed
  for Italian.
- `en` in the token-dense set — a single blockless report is a generation flake, not a
  rule to encode.

## Acceptance criteria

1. `/api/evaluate` with `lang=it` requests `max_tokens=32768` under a 480 s ceiling;
   auto-pipeline inherits the same `evalMaxTokens` (pinned red-first in the truncation suite).
2. `en` keeps the 16 384 default; the flake decision is documented, not test-encoded.
3. `mode=provider` refuses a switch to a provider with no key present; the ref guard validates
   for `mode=deploy` only, `recon`/`verify` stay dispatchable (ci-workflows gate green).
4. Full ship train: test:ci green (6841/6838/0), CHANGELOG ×19 parity, QA prompt v1.262.1
   (v1.262.0 archived), README ×19 banners, prod deploy verified.
