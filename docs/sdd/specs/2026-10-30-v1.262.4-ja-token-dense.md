# SPEC — v1.262.4: ja joins the token-dense evaluation locales

> Status: SHIPPED (the release spec; Verification filled with real output before the release merged).
> A single-purpose patch: the same deterministic wall that moved `it` (v1.262.1) and `pl`
> (v1.262.3), now caught for Japanese — this time by the full remote-QA plus a targeted
> 5-locale spot re-run that cleanly separated transients from deterministics.

## Goal

The night's full remote-QA on prod v1.262.3 (run **40981578549**, ×19) produced four
`502 · openrouter · 300 s · 0 ch` timeouts; the 5-locale spot re-run dispatched afterwards
(run **41012725839**) separated them cleanly. Three were transients — `ar` (250 s), `ko`
(291 s) and `zh-CN` (259 s) passed their reruns inside the standard 300 s clock, and `ru`'s
one-off language drift did not repeat. The fourth was deterministic: `ja` hit the standard
ceiling **twice** with zero output (`502 · 300 s · 0 ch` in both runs). Same shape class as
`ta` (v1.261.1, CAR-174), `hi`/`it` (v1.262.1) and `pl` (v1.262.3) — a token-dense locale
that cannot finish a full A–G evaluation at the standard 16 384-token / 300 s budget.
Give `ja` the token-dense budget.

## Scope

1. **`ja` → `TOKEN_DENSE_EVAL_LOCALES`** (`ta`, `hi`, `it`, `pl` → `ta`, `hi`, `it`, `pl`,
   `ja` — `server/lib/routes/llm.mjs`): both the 32 768-token budget and the 480 s clock
   apply; `/api/evaluate` and auto-pipeline stay on the one source of truth
   (`evalMaxTokens` / `evalTimeoutMs`); the 14 standard locales keep the 300 s clock.
2. **Red-first pin, incl. the clock:** `evalMaxTokens('ja') === 32768` (also `ja-JP`)
   **and** `evalTimeoutMs('ja') === 480_000` in `tests/evaluate-truncation.test.mjs` —
   both cases fail against the old maps (`ja` at 16384/300 s), green after (#608). The
   pin follows the v1.262.3 pattern: the clock pin closes the gap the v1.262.1 `it`
   patch left, for the locale that actually died on time.

**Out of scope (deliberate non-actions):**

- **`ar`, `ko`, `zh-CN` stay at the standard ceiling (300 s).** They passed their spot
  reruns at 250–291 s; the night's failures were provider-load transients, not
  deterministic walls — no evidence justifies moving them.
- **`ru`'s language drift was a one-off generation flake** — it did not repeat in the
  spot run; no pin, no locale change.
- Nothing else bundled. The README testing-table drift (`5116` — a v1.248-era count the
  sweeps kept missing because only the tree line was being updated) was fixed **en
  passant** on `main` (commit `9b37584d`, ×17 README files, `5116` → `6868`; banners now
  read `6869`) — docs-only, it rides the same release but carries no app code.

## Acceptance criteria

1. `/api/evaluate` with `lang=ja` requests `max_tokens=32768` under a 480 s ceiling;
   auto-pipeline inherits the same maps; both pinned red-first, the clock pin included.
2. The 14 standard locales keep 300 s / 16384; `ta`/`hi`/`it`/`pl` budgets unchanged.
3. Ship train: test:ci green (6868 → 6869), CHANGELOG ×19 parity, QA prompt updated,
   prod deploy verified, and a post-deploy ja evaluation re-run closes the loop.
