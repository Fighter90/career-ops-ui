## §1 — Лаунчер скана (карточка контролов)
1. Открыть `#/scan`. URL / keyword / max-per-source выстроены в ОДИН
   выровненный ряд; каждый контрол в своей «ячейке» с лейблом сверху.
2. Кнопка Run — единственная **primary** (доминирующая), остальные —
   ghost/secondary. Ширина пэддинга Run ≥ соседних кнопок (22px inline).
3. Сузить окно до 1024 → ряд переносится, контролы не наезжают друг на
   друга, min-width не даёт сжать поле URL в ноль.
4. `max-per-source`: ширина ~110px, placeholder «∞», принимает 0/пусто
   (= unlimited). Лейбл связан с инпутом (`for`/`id="max-per-source"`) —
   клик по лейблу фокусирует инпут; скринридер читает имя поля.
5. Saved-search строка под лаунчером: create → появляется в списке;
   delete — работает (в v1.247.0 кнопка станет `.btn-danger` — красная).

## §2 — Терминальная строка статуса
1. Idle: точка серая, подпись состояния. Запустить короткий скан (dry-run
   + 1 источник): точка пульсирует (running) → зелёная (done).
2. Остановить скан вручную → красная точка + Retry-баннер (не только
   toast 3.5 с). Ошибка источника не гасит общий прогон.
3. **Reduced-motion** (эмулировать `prefers-reduced-motion: reduce`):
   пульс точки отсутствует, состояние читается цветом/подписью.
4. Переключить тему → точка и подпись читаемы в dark.

## §3 — Disclosure репостов
1. Открыть `#/scan` с данными последнего скана → панель «Reposts» закрыта,
   в шапке — счётчик-бейдж.
2. Раскрыть: панель имеет **потолок высоты** (~40vh) со sticky-заголовком;
   длинный список скроллится ВНУТРИ панели, страница не растягивается.
3. Стресс (если есть старый датасет): 1,500+ кластеров не должны рендерить
   панель в 155,000 px (регрессия v1.244.0) — высота ограничена.
4. Счётчик в бейдже = числу строк в раскрытом списке.

## §4 — Фильтры как сетка
1. Блок фильтров — равномерная responsive-сетка: одинаковая ширина колонок,
   футер (Apply/Reset) выровнен по сетке.
2. 1440 / 1024 / 768 / 390: сетка перестраивается без обрезки контролов,
   «Save search» виден целиком на 390 (полная правка в v1.247.0 — здесь
   достаточно отсутствия горизонтального скролла страницы).

## §5 — Таблица результатов (hardening)
1. **Salary clamp**: строка борда с benefits-блёбом в поле зарплаты
   («$243K – $286K • Offers Equity • …401(k)…») показывает ТОЛЬКО денежную
   часть в одну строку; блоб — в tooltip (hover). Высота строки равна
   высоте строки с обычной зарплатой.
2. **Empty title**: строка с пустым title рендерит компанию (затем «—»),
   НЕ гигантскую пустую клетку.
3. **Seniority badge**: не переносится в своей колонке фиксированной
   ширины ни на одной локали (проверить на de — самые длинные слова).
4. **Unscored rows**: строки без оценки показывают приглушённое «◎ —»;
   tooltip объясняет «two-pager compare found no matching keywords».
   Рядом с оценёнными строками не выглядит сломанным.
5. **Aux-контракт**: ячейки seniority/salary в одну строку — layout-тест
   измеряет контентный элемент (`td.scan-cell-aux > *`), а не td.
